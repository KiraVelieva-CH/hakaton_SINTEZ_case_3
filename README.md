## Интерпретация результатов

После запуска анализа в консоль выводится отчет, а в папку `output/` сохраняется JSON и файл `predictions.tsv`. В отчете для каждого гена-кандидата указывается **Интегральный балл** и его составляющие. 

Для получения данных о патогенности необходимо установить базу данных от NCBI - ClinVar по ссылке: https://ftp.ncbi.nlm.nih.gov/pub/clinvar/vcf_GRCh38/clinvar.vcf.gz

Интерпретация результатов:

| Показатель в отчете | Что означает | Как рассчитывается |
| :--- | :--- | :--- |
| **Интегральный балл** | Итоговая уверенность системы в том, что этот ген вызывает болезнь. | Взвешенная сумма (Фенотип 50%, Патогенность 30%, Наследование 20%). Если каких-то данных нет, веса перераспределяются. |
| **Совпадение по HPO** | Насколько симптомы пациента совпадают с симптомами, известными для этого гена. | Пересечение HPO-терминов пациента с базой `genes_to_phenotype.txt`. Учитывается только наличие симптомов (игнорируются `excluded`). |
| **Скор наследования** | Подходит ли генотип пациента типу наследования болезни. | Сравнение зиготности (Гомозигота/Гетерозигота) с типом наследования гена (AD — доминантный, AR — рецессивный). |
| **Функциональный скор** | Подтверждена ли вредность (патогенность) самой мутации. | Поиск точного варианта в локальной базе **ClinVar**. `1.0` = Pathogenic, `0.85` = Likely pathogenic, `0.0` = Benign. |

**Специальные пометки в отчете:**
- `[+]` — Доказательство в пользу кандидата.
- `[!]` — Ограничение (Caveat). Например, отсутствие варианта в ClinVar (NA). **Важно:** отсутствие данных о патогенности не означает, что вариант безопасен, это означает «неизвестность».
- `no_causal_variant_in_vcf` — Если интегральный балл лучшего кандидата ниже `0.3`, система честно сообщает, что в предоставленном VCF нет убедительной причины болезни (например, все варианты являются фоновым шумом).

**Пример чтения отчета:**
> `КАНДИДАТ #1: Ген FBN1 (Интегральный балл: 0.967)`
> `[+] Совпадение по HPO: 0.933 (найдено 14 общих симптомов)` — *Ген отлично объясняет симптомы пациента.*
> `[+] Режим гена: AD. Генотип: Гетерозигота. Скор: 1.000` — *Для доминантного гена достаточно одной копии, у пациента она есть.*
> `[+] Функциональный скор: 1.000` — *Мутация подтверждена в ClinVar как патогенная.*

## Используемые библиотеки и технологии

Проект написан на **Python 3.10+** и использует следующие ключевые библиотеки:

- **`pydantic`** — создание строгих моделей данных (Variant, Phenotype, Candidate) и валидация типов.
- **`cyvcf2`** — высокопроизводительное чтение VCF-файлов (обертка над htslib на C). Используется для потокового чтения локальной базы ClinVar (200 МБ) без загрузки в оперативную память.
- **`pandas`** — обработка табличных данных (TSV с вариантами, база `genes_to_phenotype.txt`).
- **`requests`** — выполнение батч-запросов к REST API Ensembl VEP для функциональной аннотации.
- **`PyYAML`** — парсинг конфигурационного файла `config.yaml`.
- **`concurrent.futures`** (стандартная библиотека) — параллельный запуск анализаторов (фенотип, наследование, патогенность).

## Модуль «Оператор» (проверка входов и устойчивость)

Перед анализом система проверяет, что у неё есть, и выбирает режим работы. Итог выводится в консоль и сохраняется в JSON (`metadata.operator`).

**Что проверяется**
- Входные файлы: фенотипы, VCF или таблица вариантов. Статусы: найден, прочитан, отсутствует, не прочитан, не задан.
- Справочные базы: HPO, `genes_to_phenotype.txt`, ClinVar.

**Режимы работы**

| Режим | Когда | Результат |
|---|---|---|
| `full` | есть фенотип и варианты | ранжированные гены с конкретным вариантом |
| `phenotype_only` | только фенотип | список генов по совпадению с HPO, вариант не предсказывается |
| `variants_only` | только варианты | ранжирование по патогенности и наследованию |

**Устойчивость к сбоям**
- Модуль без входных данных или без своей базы пропускается (`пропущен`), остальные продолжают работу.
- Если модуль завершился ошибкой (`ОШИБКА`), остальные модули всё равно отрабатывают, а итоговый статус анализа становится `partial`.
- Недоступный файл не роняет программу: Оператор сообщает об этом и продолжает с тем, что есть.

**Итоговый балл**

Балл = сумма (оценка × вес) / сумма весов **использованных** оценок. Веса задаются в `config.yaml`.
- Отсутствующая оценка исключается из расчёта, рассчитанный `0` учитывается.
- Если оценок нет совсем, балл получает статус `not_calculated`.
- В отчёте для каждого кандидата выводятся: все оценки с весами, число совпавших симптомов («14 из 15»), расшифровка режима наследования (AD/AR) и генотипа, формула расчёта.

**Установка баз данных**

Большие базы не хранятся в репозитории:

```bash
mkdir -p data
wget -P data https://ftp.ncbi.nlm.nih.gov/pub/clinvar/vcf_GRCh38/clinvar.vcf.gz
wget -P data https://ftp.ncbi.nlm.nih.gov/pub/clinvar/vcf_GRCh38/clinvar.vcf.gz.tbi
```
