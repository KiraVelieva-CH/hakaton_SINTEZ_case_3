# Genomic Detective (Python 3.10+)

Учебный исследовательский прототип для приоритизации генетических вариантов по фенотипу. Он реализует структуру из ТЗ: загрузку данных, QC, четыре параллельных анализатора, интеграцию/ранжирование, проверку согласованности и объяснение результата.

> **Важно:** это не клиническая диагностическая система и не валидированный клинический бенчмарк. Результаты предназначены только для исследовательских и образовательных целей. Не используйте их для медицинских решений.

## Возможности
- Вход: фенотипы в TXT/CSV/TSV и варианты в TSV/CSV либо VCF.
- Поддержка GRCh38 как ожидаемой сборки; координаты VCF — 1-based.
- QC-флаги QUAL/DP/AF/allele balance. Варианты с флагами сохраняются для аудита.
- HPO ID можно сопоставлять через локальный `hpo_terms.tsv`.
- Четыре параллельных блока: фенотипические ассоциации, патогенность/ClinVar, простая генотипическая эвристика наследования, необязательный Exomiser-адаптер.
- Взвешенный рейтинг по доступным компонентам. Отсутствующие данные исключаются из знаменателя и явно помечаются.
- JSON и `predictions.tsv` на выходе.

## Установка

```bash
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Для VCF рекомендуется установить `cyvcf2`. На системах, где он недоступен, используется минимальный текстовый VCF-парсер для простых SNV/indel.

## Запуск

```bash
python main.py --config config.yaml \
  --phenotypes data/phenotypes.txt \
  --variants data/variants.tsv \
  --case-id case_001
```

Или передайте VCF вместо таблицы:

```bash
python main.py --phenotypes data/phenotypes.txt --vcf data/sample.vcf --case-id case_001
```

Выход:
- `output/<case_id>_analysis.json`
- `output/<case_id>_predictions.tsv`

## Формат входных данных

### Фенотипы
`phenotypes.txt`: по одному симптому/термину на строку. CSV/TSV может содержать `term` (или `phenotype`/`symptom`) и необязательный `hpo_id`.

### Варианты
Таблица должна включать `chrom`, `pos`, `ref`, `alt`; дополнительные колонки:
`gene`, `variant_id`, `consequence`, `genotype`, `qual`, `depth`, `allele_balance`, `population_af`, `clinvar_significance`, `clinvar_review_status`, `alphamissense`, `spliceai`.

Пример:
```tsv
chrom	pos	ref	alt	gene	genotype	population_af	clinvar_significance
1	123456	A	G	GENE1	0/1	0.0001	Uncertain significance
```

### Локальные справочники (опционально)
Файлы в `resources` в `config.yaml` — TSV:
- `gene_phenotype.tsv`: `gene`, `hpo_id` (или `term`)
- `clinvar.tsv`: `variant_id`, `significance`, `review_status`
- `hpo_terms.tsv`: `term`, `hpo_id`

Справочники не поставляются: подключайте версии с указанием источника, даты и лицензии. Не смешивайте сборки генома.

## Настройка внешних сервисов

По умолчанию сеть и OpenAI отключены. Для Ensembl VEP:
1. Убедитесь, что координаты относятся к указанной сборке.
2. В `config.yaml` установите `analysis.allow_network: true` и `analysis.use_vep: true`.
3. Проверьте ограничения и доступность Ensembl REST API.

Для LLM установите `analysis.use_openai: true` и задайте `OPENAI_API_KEY` в окружении. LLM получает только сформированный JSON-факт-пакет; её текст всё равно требует проверки. Ключ не храните в `config.yaml`.

Для Exomiser укажите `analysis.exomiser_command`. Протокол адаптера: команда получает JSON-контекст через stdin и должна вернуть JSON с объектом `genes`, где для каждого гена может быть поле `score` от 0 до 1. Это тонкий адаптер: для реальной установки Exomiser обычно потребуется собственный конфигурационный файл и преобразование входных данных.

## Интерпретация и ограничения
- Встроенный phenotype analyzer использует только локальный файл ассоциаций. Без него фенотипический балл равен 0, а не означает отсутствия связи.
- Встроенная наследственная эвристика смотрит только на GT и не знает семейную сегрегацию, пол, полигенность, митохондриальные варианты или конкретный режим наследования заболевания.
- Pathogenicity analyzer использует ClinVar-значения, переданные во входе/локальном TSV, и функциональные оценки, если они уже присутствуют. Он не скачивает ClinVar, gnomAD, AlphaMissense или SpliceAI автоматически.
- VEP — единственная внешняя аннотация, реализованная как опциональный REST-запрос. gnomAD, OMIM/Orphanet/ClinGen и Phen2Gene/LIRICAL требуют отдельного лицензированного/версионированного интеграционного слоя.
- Наличие в рейтинге не означает причинность. Отсутствие кандидата не исключает генетическую причину.
- QC-флаги не удаляют вариант автоматически: решение оставлено для последующей экспертной проверки.
- Результат `no_causal_variant_in_vcf` допустим как вывод исследователя, но текущая версия не присваивает его автоматически без заданных критериев полноты/покрытия.
